# SentinelCore SecureOps — Database Schema

## 1. Database

Database: PostgreSQL

The database is designed to support the SentinelCore SecureOps
Infrastructure Monitoring system.

---

## 2. Assets

The `assets` table stores all infrastructure assets that are monitored
by the system.

### Table: `assets`

| Column | Data Type | Constraints | Description |
|---|---|---|---|
| id | BIGSERIAL | PRIMARY KEY | Unique asset ID |
| name | VARCHAR(100) | NOT NULL | Asset name |
| type | VARCHAR(50) | NOT NULL | Asset type such as SERVER or VM |
| ip_address | VARCHAR(45) | | IP address of the asset |
| location | VARCHAR(150) | | Physical or logical location |
| created_at | TIMESTAMP | NOT NULL | Asset creation timestamp |
| updated_at | TIMESTAMP | NOT NULL | Last update timestamp |

---

## 3. Infrastructure Metrics

The `infrastructure_metrics` table stores resource utilization
measurements for monitored assets.

### Table: `infrastructure_metrics`

| Column | Data Type | Constraints | Description |
|---|---|---|---|
| id | BIGSERIAL | PRIMARY KEY | Unique metric record ID |
| asset_id | BIGINT | NOT NULL, FOREIGN KEY | ID of the monitored asset |
| cpu_usage | DECIMAL(5,2) | | CPU utilization percentage |
| memory_usage | DECIMAL(5,2) | | Memory utilization percentage |
| disk_usage | DECIMAL(5,2) | | Disk utilization percentage |
| network_in | DECIMAL(12,2) | | Incoming network usage |
| network_out | DECIMAL(12,2) | | Outgoing network usage |
| timestamp | TIMESTAMP | NOT NULL | Time when the metrics were recorded |

### Relationship

One asset can have multiple metric records.

```text
assets (1) ──────────── (N) infrastructure_metrics

---

## 4. Cloud Resources

The `cloud_resources` table stores monitored cloud resources.

### Table: `cloud_resources`

| Column | Data Type | Constraints | Description |
|---|---|---|---|
| id | BIGSERIAL | PRIMARY KEY | Unique cloud resource ID |
| name | VARCHAR(100) | NOT NULL | Cloud resource name |
| resource_type | VARCHAR(50) | NOT NULL | Type of cloud resource |
| provider | VARCHAR(50) | NOT NULL | Cloud provider |
| region | VARCHAR(100) | | Cloud region |
| status | VARCHAR(50) | NOT NULL | Current resource status |
| created_at | TIMESTAMP | NOT NULL | Resource creation timestamp |

---

## 5. Network Metrics

The `network_metrics` table stores network monitoring information.

### Table: `network_metrics`

| Column | Data Type | Constraints | Description |
|---|---|---|---|
| id | BIGSERIAL | PRIMARY KEY | Unique network metric ID |
| network_name | VARCHAR(100) | NOT NULL | Network name |
| status | VARCHAR(50) | NOT NULL | Current network status |
| network_in | DECIMAL(12,2) | | Incoming network traffic |
| network_out | DECIMAL(12,2) | | Outgoing network traffic |
| latency | DECIMAL(10,2) | | Network latency |
| packet_loss | DECIMAL(5,2) | | Packet loss percentage |
| timestamp | TIMESTAMP | NOT NULL | Time when metrics were recorded |

---

## 6. Alerts

The `alerts` table stores security and infrastructure alerts generated by the monitoring system.

### Table: `alerts`

| Column | Data Type | Constraints | Description |
|---|---|---|---|
| id | BIGSERIAL | PRIMARY KEY | Unique alert ID |
| asset_id | BIGINT | FOREIGN KEY | Related monitored asset |
| alert_type | VARCHAR(50) | NOT NULL | Type of alert |
| severity | VARCHAR(20) | NOT NULL | Alert severity |
| message | TEXT | NOT NULL | Alert description |
| status | VARCHAR(30) | NOT NULL | Current alert status |
| created_at | TIMESTAMP | NOT NULL | Alert creation timestamp |
| acknowledged_at | TIMESTAMP | | Time when alert was acknowledged |

### Relationship

An asset can have multiple alerts.

```text
assets (1) ──────────── (N) alerts
